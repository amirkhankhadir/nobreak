# Nobreak

Плагин Figma: находит в макете места, где короткое служебное слово оказалось последним в строке — «висит», — и склеивает его со следующим словом неразрывным пробелом. Заодно проверяет сокращения («ул. Абая», «п. 3»), число с единицей, знак номера, валюту и лишние пробелы.

Главное про принцип: плагин ищет **только то, что висит на текущем размере макета**. Переносы строк он не вычисляет сам, а читает у Figma — поэтому показывает ровно то, что видно на экране. Текст, который физически не может перенестись (ширина по содержимому, одна строка), находок не даёт.

## Что нужно

Десктопное приложение Figma — плагин из локального манифеста в браузерной версии не поставить.

## Установка

1. Скачайте папку `nobreak` и положите куда угодно на компьютере. Внутри три файла плагина — `manifest.json`, `code.js`, `ui.html`. Держите их вместе.
2. Откройте приложение Figma и любой файл.
3. Меню сверху: Plugins → Development → Import plugin from manifest…
4. Выберите `manifest.json` из папки.
5. Готово. Плагин появится в Plugins → Development → Nobreak.

Запускайте его именно из этого меню. Комбинация ⌥⌘P перезапускает последний плагин, а не выбранный.

## Как пользоваться

1. Выберите область: **Выделение** (выделенные слои), **Страница** или **Файл** (с фильтром страниц). На больших файлах выделить фрейм и проверить выделение намного быстрее, чем гонять весь файл.
2. При необходимости откройте **Правила** и выключите лишние. Правила влияют на следующую проверку.
3. Нажмите **Проверить**. Долгую проверку можно прервать кнопкой **Отменить**.
4. Находки сгруппированы по правилам. В строке видно место находки: метка показывает пробел, который меняется. Справа — экран, на котором лежит текст.
5. Клик по строке показывает слой на канвасе. Пока слой выделен, строка подсвечена.
6. Правьте как удобно: **Исправить** в строке, **Исправить все** в шапке группы или **Исправить всё** в подвале. Отменить всё сразу — Cmd + Z, плагин пишет одной операцией.

## Статусы

- **Исправим** — плагин поправит сам.
- **Нельзя** — Figma не даёт переписать этот текст. Такие находки собраны в группу по причине, а не по правилу, — сейчас причина одна: «Текст из переменной». Правьте переменную в панели Variables.
- **Не проверено** — сюда плагин посмотреть не смог, поэтому находки внутри не показывает. Таких групп две: «Скрытые слои» и «Не смог прочитать раскладку строк». У второй причина своя у каждого слоя и написана в строке справа: нет нужного шрифта, слой не экспортируется, в экспорте нет текста, раскладка не сошлась с текстом.

  Про шрифт стоит знать одно: Figma сообщает о нехватке не всегда надёжно. Если она промолчала, плагин прочитает раскладку, отрисованную подменным шрифтом, — ту же, что видите на экране вы. То есть совет будет верен для вашей машины, но может не совпасть с машиной, где шрифт установлен.

## Что важно знать

- **Результат верен для текущего размера макета.** Поменяли ширину блока — проверьте заново. Плагин намеренно не правит «на будущее»: макет уезжает разработке в фиксированном размере.
- **Размер слоя.** Неразрывный пробел меняет перенос, и текст может занять больше строк. После правки плагин сравнивает размер слоя до и после и показывает изменившиеся, с кнопкой **вернуть**.
- **Форматирование не слетает.** Плагин меняет отдельные символы, а не перезаписывает строку целиком, поэтому жирные фрагменты, ссылки и цветные слова остаются на месте. Кнопка «вернуть» работает так же — обратными точечными правками. Это касается и текста, заданного свойством компонента: если внутри есть разные стили, плагин правит символы, а не значение свойства, потому что значение — плоская строка и схлопнуло бы цвета. Проверено на живом файле: точечная правка привязанного к свойству текста сама обновляет значение свойства — лишнего оверрайда не появляется.
- **Мастер-компоненты плагин правит наравне с инстансами.** Если файл — опубликованная библиотека, правка уедет потребителям при обновлении.
- **Лишние пробелы** — двойные и по краям строк — находятся всегда, независимо от переносов: это дефект текста при любой раскладке.
- **Обрезанный текст** (кнопка с эллипсисом) проверяется только по видимым строкам.
- **Скрытые слои** по умолчанию не проверяются: у невидимого текста нет переносов. Если нужно — включите галочку «Показывать скрытые слои» под выбором области. Такие слои попадут в группу «Скрытые слои»; покажите слой и проверьте снова.
- **Чего плагин не делает:** не трогает «ё», кавычки, десятичную запятую и формулировки — это работа для человека, а не для пакетной замены.

## Как это устроено внутри

Раскладку строк плагин узнаёт так: экспортирует текстовый слой в SVG и читает, на какие строки Figma разбила текст. Экспорт только читает — файл не меняется и история отмены не растёт. У каждого слоя есть самопроверка: склейка прочитанных строк должна совпасть с текстом слоя. Не совпала — слой помечается как непроверенный, а не разбирается наугад.

Скорость: слои, которые не могут перенестись, отбрасываются без экспорта — на живом макете это четверть. Остальным нужен экспорт, около 5 мс на слой. Замер: страница из 1639 текстовых слоёв проходит за 9,5 секунды. Долгую проверку можно прервать кнопкой «Отменить», а на больших файлах быстрее выделить нужный фрейм и проверить выделение.

Документ плагин загружает целиком, а не по мере надобности. Ленивая загрузка страниц (`documentAccess: dynamic-page`) для такой задачи не подходит: `page.loadAsync()` подтягивает дерево страницы, но не начинку инстансов, и на реальном макете это давало 59 слоёв вместо 1639 — область «Файл» молча пропускала почти всё, кроме открытой страницы.

## Для разработки

Тесты детектора: `node tests/detector.test.mjs`. Сборки нет — `code.js` работает и как плагин, и как модуль Node: обвязка Figma внутри него не запускается, если объекта `figma` нет.
